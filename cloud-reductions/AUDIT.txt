Scope: node/edge representation permutations with physical geometry, graph, stored
birth times, genotype and plant/ancestry identity preserved. Reversing plant

R1 has no persisted numerical state or cache, so saved replay recomputes the same
physical order. No physics tolerance, floor, packet bill, rate or transport mixing
coefficient changes.

Canonical physical chronology
Initial seed_shape creates collar, upper stem, root, +x leaf, -x leaf, +z leaf,
-z leaf at the SAME stored birth tick. That exact written order is used as a stable
physical tie convention, not an inferred age difference. Later paid cells are
committed in world.resolve_growth's existing sorted spatial-position order within
each tick. Sorting by birth then those physical ranks reconstructs append order
on unpermuted valid shared-world histories. Current births AND every subsequent
hour of new trials/replays assert that reconstruction. Thus existing control
addition order/reserve traversal is preserved, not replaced by a new allocation
preference. Physically duplicate coordinates/keys are rejected, never ordered by ID.
The seed-specific constructor ordering is deliberately retained for compatibility;
it is not proposed as universal plant biology.

Arithmetic guarantee and bounds
The same operands/formulas, added in the same physical sequence, yield identical
binary64 reductions for equivalent inputs on this tested runtime. This is not
mathematically exact summation or an across-platform guarantee. Standard finite
sum error bound gamma_m*sum(abs(x)), gamma_m=m*u/(1-m*u), u=2^-53; long-lived stocks
include their whole addition history. Near a discontinuity this error may matter;
R1 does not add epsilon or change the discontinuity. All conservation/positivity
checks stay enabled. Floats are never clamped or repaired to force a ledger match.
