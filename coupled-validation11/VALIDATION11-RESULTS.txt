COUPLED11 VALIDATION CHECKPOINT — NATIVE CPU AND QUANTIZATION

FINDING
The compiled CPU field backend is faster for this2184-cell coupled workload. Coupled10's apparent GPU advantage was against interpreted field code. Do not use that earlier timing to justify replacing the backend.
Resource precision also matters: coarse quanta alter represented inventory, uptake and plant topology. The three finest tested quanta(1e-8,1e-9,1e-10) matched funded topology at every recorded tick for both tested seeds, but their resource uptake values were not identical. This is bounded evidence, not universal convergence or species calibration.
The reviewed Coupled10 application, package, shortcuts and biological rules remain unchanged. Native code and all experimental variants are confined to coupled-validation11/. No installation, persistent access, MCP registration, credential or network change occurred.

FAIR NATIVE COMPARISON
NativeResourceField is an in-process Godot GDExtension written in C, compiled with the already installed MinGW-w64 GCC13.2.0 using -O3 -g -std=c11 -shared. It uses resident ping-pong uint32 cell arrays, exact int64 intermediates/uint64 totals, sequential bounded exchanges, the same sparse query results and diagnostics. No external-process IPC is used. The installed Godot4.7.2 engine generated its matching ABI header; the header's license and GODOT-LICENSE.txt are retained. DLL imports are only existing Windows/UCRT APIs(listed in evidence/native-dependencies.txt).
This compiles the resource backend, not the entire biological model. Both CPU and GPU paths call the SAME unchanged GDScript physiological/construction functions and equivalent coupling/diagnostic work. Rewriting biology into C would introduce another source of differences and is outside this checkpoint. The native code is a single-threaded optimized reference, not a claim of the fastest possible CPU implementation.
Hardware: AMD Ryzen7 7800X3D(8cores/16threads) and NVIDIA RTX5070Ti, driver610.88; hardware.json retains the system-reported versions. Other user applications were left running; these are bounded local measurements, not an isolated hardware certification.

Three backends were measured: native_cpu, the original reviewed Coupled10 GPU algorithm at1e-9(gpu_original), and the wide-accounting validation GPU(gpu_wide). At1e-9 they have identical complete field-and-plant fingerprints. All six seed/preset baseline fingerprints also match the reviewed Coupled10 results. The original GPU copy differs only in resource-path wiring and a scale accessor; its numerical kernel is retained unchanged.
One warm-up triplet preceded six measured triplets. All six execution-order permutations were used. Seed12011, fed preset,96ticks, same grid, boundaries, initial quantized inventories and update order. Every tick runs the same guard, metrics and quick signature after simulation. The endpoint audit reads full fields and hashes the complete state. All18measured endpoints matched exactly and were healthy.

PRECISION SWEEP
Tested physical quantum1e-5,1e-6,1e-7,1e-8,1e-9,1e-10model units; scales are their reciprocals. Seeds12011and4242, fed/water-absent/nitrogen-absent presets,96ticks each:36paired cases and3456paired ticks. No biological parameter, seed, timestep, deposit schedule, starvation preset, threshold or branching rule was retuned.
Each precision begins from the SAME unquantized physical field formula, rounded to its grid. Reservoir quantities and pulse sizes keep the SAME physical values. Uptake requests truncate downward to quanta. Precision therefore changes both initial represented inventories and per-step flux/uptake truncation; these effects were not separated by compensating totals or silently normalizing fields.
Conservative face diffusion remains W:trunc(3*delta/100), N:trunc(2*delta/100)in integer units, with no-flux boundaries. Signed face fluxes are equal/opposite. A difference of34W-quanta or50N-quanta is needed for a nonzero one-quantum flux. At coarse precision, small gradients stall while total mass remains conserved. Native/GPU field inventories are exact integers; plant ledgers remain floating point under the unchanged biological code.

RANGE / OVERFLOW RULES
Reviewed Coupled10 uses uint32 field totals. At quantum1e-9 its maximum representable total is4.294967295units, enough for the bounded~4.12water budget. At1e-10that same accumulator would represent only0.4294967295units and cannot support the fed case; using it would be invalid.
Validation therefore uses two32-bit limbs for each GPU total(with explicit carry) and uint64 native totals. Cell storage remains uint32, physically capped at0.1units. At the finest tested precision, each cell holds at most1,000,000,000quanta, and the entire2184-cell domain at most2,184,000,000,000quanta(218.4units). These are the validated bounds, not the theoretical capacity of an unconstrained uint64 total.
The GPU avoids signed32-bit product overflow through an exact quotient/remainder decomposition: trunc(delta/100)*coefficient + trunc((delta-trunc(delta/100)*100)*coefficient/100). The native CPU computes the equivalent expression with int64 intermediates. Precision1e-11is explicitly rejected BEFORE GPU allocation because its per-cell range exceeds the validated bound. Fixed-grid dimensions, cell capacities, finite inventory and command limits remain bounded.
Seven additional range checks passed: maximum-cell impulse and maximum uniform field, exact wide totals above2^32, positivity, full native/GPU agreement, and rejection of unsupported finer precision. They exercise the overflow-sensitive cases directly, beyond ordinary plant inventories.

NEGATIVE EVIDENCE AND REPAIRS
The first native class registration crashed because empty native String metadata was not initialized. Its source and raw crash logs are retained in evidence/native-registration-failure/. Initializing the metadata removed the crash; final native smoke, all numerical suites and review stderr are clean. This is a local reference-module repair, not a change to the reviewed application.
The first wide GPU flux decomposition used signed %. It failed conservation/reference checks immediately. The installed SPIR-V tool confirms that expression compiled to OpSMod, while division compiled to OpSDiv. Explicitly reconstructing the truncating remainder restored equal/opposite signed fluxes and exact agreement. Original shader, failed output and disassembly are retained in evidence/signed-remainder-failure/. These failed runs are NOT included as successful results. Original Coupled10's GPU kernel did not contain this introduced decomposition and was never modified.
The initial two-backend timing set is retained under evidence/initial-wide-benchmark/; the final three-backend set is native-benchmark.json. No allocation failure occurred in these final runs. Memory safeguards refused launch below3GiB commit headroom and would stop only the owned validation process below1GiB or at150seconds. Peak observed working set was about1.09GB, sampled private commit1.30GB; sampling100ms. No unrelated application was closed.
